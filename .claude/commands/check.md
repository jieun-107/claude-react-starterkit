커밋 전 검증을 실행한다. 각 단계는 앞 단계가 통과한 뒤에 진행한다.

## 실행 순서

1. `npm run typecheck` — 타입 검사
2. `npm run lint` — ESLint
3. `npm run format:check` — Prettier 검사 (쓰기 아님)
4. `npm run test` — Vitest 1회 실행

## 실패 시 처리

- 실패한 단계에서 멈추고, 오류 메시지 핵심 줄을 인용한다.
- 원인을 분석하고 수정안을 제안한다. 수정은 사용자가 승인한 뒤에만 한다.
- 포맷 오류만 있으면 `npm run format`으로 고칠 수 있다고 안내하되, 자동으로 실행하지는 않는다.
- 테스트 실패 시 실패한 테스트 이름과 기대값/실제값을 요약한다.

## 통과 시 처리

1. 변경 내용을 `git status`와 `git diff --stat`으로 확인하고 요약한다.
2. 한국어 커밋 메시지 초안을 제안한다.
   - 형식: `<타입>: <한국어 요약>` (타입은 `feat`, `fix`, `docs`, `chore`, `refactor` 중 하나)
   - 최근 `git log --oneline -5`의 스타일을 따른다.
3. 커밋은 하지 않는다. 사용자가 요청하면 그때 커밋한다.

## 출력 형식

| 단계 | 결과 |
|---|---|
| typecheck | 통과 / 실패 |
| lint | 통과 / 실패 |
| format:check | 통과 / 실패 |
| test | 통과 / 실패 (통과 개수) |
